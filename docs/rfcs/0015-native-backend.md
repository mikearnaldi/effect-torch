# RFC 0015: Native Backend — Replacing Candle

- **Status**: Draft
- **Created**: 2026-08-03
- **Depends on**: RFC 0007 (fusion), RFC 0010 (inference), RFC 0012 (dtypes), RFC 0013 (batched decode)
- **Updates**: —

## Summary

Remove candle entirely. Implement the tensor backend from scratch —
CPU and Metal first, CUDA later — designed for exactly what the lazy
graph needs, with our semantics for the layers that determine
performance: allocation, encoder management, synchronization, and
kernel fusion. No vendoring: candle's design decisions (eager
tensor-first API, per-op dispatch structure, storage-mode and pool
policies, hazard-tracking machinery) are not inherited; they are
replaced.

## Motivation

The 0.9.2 → 0.11.0 rebase made the structural problem concrete.
Upstream redesigned its allocator and encoder layer; training
regressed 2.8s → 3.8s; a full day of instrumentation found the fixes
were re-imposing *our* semantics (probe-based pooling, bucket caps,
rate-limited sweeps, shared intermediates, one device-global sync)
inside their codebase. Upstream additionally shipped broken
(`--features metal,ug` does not compile on 0.11.0), and its
hazard-tracking design costs CPU per dispatch forever to solve a
problem serial dispatch semantics don't have.

What candle still provides is small and shrinking: commodity CPU/Metal
op implementations, the mlx gemm, and the Tensor/Layout types. The
training-critical path is already ours: graph, autodiff, evaluator,
fusion compiler, flash attention fwd/bwd, CE loss, LayerNorm, rotary,
paged attention, kv scatter, gemm+bias epilogue, optimizer fusion.

We are not rewriting a general-purpose tensor library. The graph layer
fixes the exact contract: the op set in `NodeKind`, the strict dtype
tiers of RFC 0012, and only the layout patterns the evaluator
produces. That is a ~40-op backend with known usage, not an
800k-line framework.

## Design

### Core runtime (`runtime.rs` and friends in `packages/native/src`)

- `Tensor { storage: Storage, layout: Layout, dtype: DType }` — the
  only tensor type; replaces candle's at the napi boundary and in
  every eval arm.
- `Layout { shape, strides, offset }` — explicit strided semantics;
  views are free, materialization is explicit (`contiguous()`).
- `DType` — exactly RFC 0012: f32/f64/f16/bf16 compute; u8/u32/i64
  integer; storage-only int8 behind bespoke kernels. The Node::new
  capability matrix stays the single strictness choke point.
- `Storage = Cpu(Vec-backed) | Metal(Buffer)` with an `Arc` pool
  reference; no eager/lazy split — the graph above is the only lazy
  layer.
- `Device` trait: `allocate`, op kernels, `synchronize`. Two impls:
  `CpuDevice`, `MetalDevice`. CUDA later as a third, following the
  Metal template.

### CPU backend

- Generic strided elementwise/unary/binary via macro-generated loops
  over the RFC 0012 dtype set; broadcasting by stride-0.
- Reduces (sum/max/min/argmax) over arbitrary strided axes.
- Matmul: Accelerate (`cblas_sgemm`) for f32; loop nests for other
  dtypes initially.
- Indexing: gather/scatter/scatter_add/index_select, strided.
- Cast (all tier-legal pairs), fill, concat, narrow, copy.
- Random: xoroshiro128+ (seeded; deterministic for tests).
- im2col stays composed at the graph layer (as today).
- No quantized formats, no gguf, no conv kernels, no sort kernels
  beyond what sampling needs.

### Metal backend

- **Allocator**: the semantics we proved out — power-of-two buckets,
  rotating 8-probe reuse, bucket cap 4096, rate-limited dead-entry
  sweep (`CANDLE_POOL_SWEEP_MS` equivalent), StorageModeShared
  intermediates (Private is opt-in). No find_available_buffer scans.
- **Encoder/commands**: 0.9.2-class serial semantics — one compute
  encoder per command buffer, `MTLDispatchType::Serial` (implicit
  in-encoder ordering), no hazard tracking, no fences, no barriers;
  command buffers retired at a configurable dispatch count; one
  device-global `synchronize`. This is correct on Apple silicon for
  our dispatch patterns and has none of the per-bind tracking cost.
- **Kernel library** (runtime-compiled, cached, as today):
  - Elementwise/unary/reduce/cast: **generated by our own fusion
    compiler**. The RFC 0007 IR is ours; ug was only ever an
    MSL/PTX emitter behind it (the CPU path already interprets the IR
    directly). The backend includes a direct IR → MSL emitter (~a few
    hundred lines for the fusion op set), which also unlocks what ug
    cannot express well: 128-bit vectorized loads, f16/bf16 lanes,
    our exact reduce patterns. ug is dropped like candle — it needed
    a fork (7 added ops) to serve us, which is the same structural
    signal. A CUDA emitter follows the same IR later.
  - Matmul: tiled simdgroup gemm written for our shapes (MLX-class
    tile selection as the reference); the gemm+bias epilogue from
    gemm.rs carries over directly.
  - Indexing: gather/scatter/scatter_add/index_add (incl. u8 variants
    for int8 kv), concat copy, fill, copy2d.
  - Random: xoroshiro128+ kernels (init, dropout).
  - Already ours and unchanged: flash fwd/bwd, paged attention, kv
    scatter, CE loss, LayerNorm, rotary — they talk to raw Metal
    objects today and need only re-pointing at the new device wrapper.
- Readback: direct map for shared buffers; blit copy for private.

### Migration (no flag day, no vendoring)

The new runtime lands as new modules in `packages/native/src` beside
the candle-backed eval arms. Eval arms switch **device by device, op
by op** behind the same napi surface; the test suite (CPU+Metal, 601
tests) is the parity harness at every step. Candle is a dependency
until the last eval arm moves; then the dependency, the forks, and the
rev pins are deleted.

1. **Phase 0 — inventory**: exact op × layout × dtype surface the
   evaluator dispatches (from `NodeKind` eval arms), as a checklist.
2. **Phase 1 — core runtime + CPU backend**: Tensor/Layout/Storage/
   Device + full CPU op set; CPU eval arms switch; suite green with
   candle only serving Metal.
3. **Phase 2 — Metal device**: allocator, encoder manager, kernel
   library, the IR → MSL emitter wired into fusion.rs; Metal eval
   arms switch; suite green with no candle and no ug.
4. **Phase 3 — deletion**: candle + fork rev pins removed; napi
   boundary exposes only our Tensor.
5. **Phase 4 — CUDA** (later): an IR → PTX emitter and a CUDA device
   impl on the Metal template.

### What stays

tokenizers (independent crate), objc2/objc2-metal (stable Apple
bindings), Accelerate (CPU BLAS), every hand-written kernel of the
optimization campaign, the entire graph layer. ug does **not** stay:
it is replaced by a first-party emitter behind the existing fusion IR.

## Risks

- **CPU parity is the iceberg**: the op set is small but strided
  correctness across dtypes is fiddly. Mitigation: the existing suite
  runs every op on CPU already; phases stay green; no estimate
  promises beyond phase gates.
- **Metal driver edge cases** candle absorbed over years (device
  enumeration, seed buffer sizes, readback races). Mitigation: the
  rebase audit enumerated them; the device layer is written with those
  lessons listed in the phase-2 checklist.
- **Gemm quality**: a naive tiled gemm is ~half of mlx gemm on some
  shapes. Mitigation: matmul is one kernel; iterate with the kind
  timing harness; port MLX tile-selection heuristics if needed.

## Acceptance criteria

1. Zero candle dependencies in `packages/native/Cargo.toml`; the
   candle and ug forks' rev pins deleted.
2. Full suite (CPU + Metal) green, 601+ tests, unchanged semantics.
3. nano-gpt compiled training ≤ 2.8s/400 steps; generation unchanged.
4. Memory bounded in the GC-deferred-release regime (the pool
   invariants of the optimization campaign preserved by design).
5. RFC 0007 fusion pipeline, RFC 0010 inference stack, RFC 0012 dtype
   strictness, RFC 0013 batching all function on the new backend
   without graph-layer changes.
